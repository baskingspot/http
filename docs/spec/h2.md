# HTTP/2 framing: references and choices

The frame codec in `src/h2/frame.zig` is written from RFC 9113, not ported from
an implementation. h2c and h2 over TLS use the same frames; nothing in this
module touches TLS or reads the connection preface.

## Normative references

- [RFC 9113](https://www.rfc-editor.org/rfc/rfc9113): HTTP/2. §3.4 connection
  preface, §4.1 frame format, §4.2 frame size, §5.1 stream identifiers, §6.1
  DATA, §6.2 HEADERS, §6.3 PRIORITY, §6.4 RST_STREAM, §6.5 SETTINGS, §6.6
  PUSH_PROMISE, §6.7 PING, §6.8 GOAWAY, §6.9 WINDOW_UPDATE, §6.10
  CONTINUATION, §7 error codes.
- [RFC 7541](https://www.rfc-editor.org/rfc/rfc7541): the field block carried
  by HEADERS and CONTINUATION.
- [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110): field names, values, and
  status codes, referenced by §8.2.1 of HTTP/2.
- [RFC 8441](https://www.rfc-editor.org/rfc/rfc8441): extended CONNECT and the
  `:protocol` pseudo-header.
- [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986): scheme and authority
  syntax.

## Choices

| Subject | RFC | Choice |
| --- | --- | --- |
| Unknown frame types | 9113 §4.1 (MUST ignore) | `body` returns `Body.unknown` with the raw payload; the caller discards it. |
| Unused flags | 9113 §4.1 (MUST ignore on receipt) | Left in `Header.flags`; the payload parser checks only the flags it defines. |
| Reserved stream bit | 9113 §4.1 (MUST ignore on receipt, zero on send) | Masked off on parse; zero on encode. |
| Payload above SETTINGS_MAX_FRAME_SIZE | 9113 §4.2 | `parse` takes the current maximum and returns `error.FrameTooLarge` before waiting for the payload. The caller maps it to FRAME_SIZE_ERROR. |
| Fixed payload lengths | 9113 §6.3–6.10 | PRIORITY 5, RST_STREAM 4, PING 8, GOAWAY at least 8, WINDOW_UPDATE 4, SETTINGS a multiple of 6, ACK SETTINGS empty. Anything else is `error.InvalidLength`, which maps to FRAME_SIZE_ERROR. |
| Padding | 9113 §6.1, §6.2, §6.6 | Stripped from DATA and the block fragments. A pad length that covers the whole payload is `error.InvalidPadding`, which maps to PROTOCOL_ERROR. Padding bytes are not checked for zero. |
| PRIORITY in HEADERS | 9113 §6.2 | Parsed when the flag is set; priority signaling is deprecated but the fields are still on the wire. |
| WINDOW_UPDATE of zero | 9113 §6.9 | Kept as the wire value; the flow-control layer rejects it. |
| Stream 0, frame ordering, SETTINGS values | 9113 §5.1, §6.5, §4.3 | Not checked here. The frame codec is syntax only; the stream and connection layers own those rules. |
| CONTINUATION | 9113 §4.3, §6.10 | Parsed as a fragment. Assembly across frames belongs to the layer above. |
| Partial reads | — | `parse` returns `error.Incomplete` until the 9-byte header and all `Length` payload bytes are present. The header carries the length, so there is no rescan cursor like HTTP/1. |
| Writing | — | `Writer` fills a caller buffer: `begin` reserves the 9-byte header, `bytes`/`int` append the payload, `end` patches the 24-bit length. A short buffer is `error.NoSpace` and leaves the partial frame at `pos`. |

## Field sections

`h2.head.request` and `h2.head.response` take the field list the HPACK decoder
produced, pseudo-headers included, and return a typed head plus a `Headers`
view of the regular fields. Every slice is borrowed; the head owns nothing.

| Subject | RFC | Choice |
| --- | --- | --- |
| Field names | 9113 §8.2.1 | Lowercase `tchar` only. Stricter than the RFC's minimal list of forbidden bytes, and the same rule HTTP/1.1's parser applies. |
| Field values | 9113 §8.2.1, 9110 §5.5 | NUL, CR, LF, other controls, DEL, and edge SP/HTAB are rejected. HTAB inside a value and obs-text are allowed. |
| Pseudo-header order | 9113 §8.3 | Pseudo-headers must precede regular fields. A pseudo after a regular field is `PseudoAfterField`. |
| Pseudo-header duplication | 9113 §8.3 | One of each; a repeat is `DuplicatePseudo`. |
| Pseudo-header names | 9113 §8.3.1, §8.3.2, RFC 8441 | Requests: `:method`, `:scheme`, `:authority`, `:path`, `:protocol`. Responses: `:status`. Anything else is `UnknownPseudo`. |
| Required request fields | 9113 §8.3.1 | `:method`, `:scheme`, and `:path`, unless CONNECT. |
| CONNECT | 9113 §8.5 | `:scheme` and `:path` omitted; `:authority` required. |
| Extended CONNECT | RFC 8441 | `:protocol` present with CONNECT, and `:scheme`, `:path`, `:authority` required. `:protocol` without CONNECT is `InvalidProtocol`. |
| `:path` | 9113 §8.3.1 | Non-empty and absolute. `*` is accepted only for OPTIONS. |
| `:scheme` | RFC 3986 §3.1 | ALPHA, then ALPHA / DIGIT / `+` / `-` / `.`. Not limited to http and https. |
| `:authority` | 9113 §8.3.1 | Non-empty. Userinfo (`@`) is rejected for http and https. Host and port syntax is left to the URI layer. |
| `:status` | 9113 §8.3.2, 9110 §15 | Exactly three digits. The value is an open `Status`; the caller applies the 100..599 class rule. |
| `:method` | 9113 §8.3.1, 9110 §9.1 | A non-empty token. `Method.parse` fills the common enum, and `method_token` keeps the exact bytes. |
| Connection-specific fields | 9113 §8.2.2 | `connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, and `upgrade` are rejected. `te` must be exactly `trailers`, case-insensitively. |
| Cookies | 9113 §8.2.3 | Not combined. The caller combines `cookie` lines with `"; "` where it wants the joined value. |
| `host` and `:authority` mismatch | 9113 §8.3.1 (SHOULD malformed) | Not checked; normalization is the caller's policy. |
| Malformed section | 9113 §8.1.1 | A stream error of type PROTOCOL_ERROR. `h2.head.Error` carries the reason. |

## h2c and TLS

h2c and h2 share every frame. The only differences sit below this module: the
client preface (`frame.preface`) and, for h2, ALPN during the TLS handshake.
The server's first frame after the preface is SETTINGS in both cases. Nothing
in the codec needs a TLS type.
