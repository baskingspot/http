# Client request-body streaming

The v0.1 client keeps `Request.body` as a static slice; the next shape is a writable request body, not a reader the adapter drains: the caller supplies `write(bytes)` and `close()`, and the adapter appends frames only while the frame queue has no partially written frame, using the queue’s existing END_HEADERS commit and END_STREAM completion split. Request-body bytes stay borrowed until `Body.close`: on the h2 early-response path `request()` may return with body bytes pending, and `Body.read`/`Body.close` must send the remainder under flow control (applying response-read backpressure) or reset an incomplete stream with NO_ERROR; the connection is not reusable until the body is sent or the stream reset. h1 has no early-response path: it sends the whole body and flushes it before parsing the response. Client streaming and trailers remain out of scope for v0.1; when trailers arrive they must be snapshotted into the response arena at EOF, not exposed lazily from the connection buffer, so a `trailers()` accessor stays readable after EOF.
